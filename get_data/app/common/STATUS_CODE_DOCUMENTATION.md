# 赛事状态码说明文档

## 概述

本文档详细说明系统中使用的赛事状态编码体系，用于统一管理所有赛事类型（足球、篮球等）的状态流转。

## 状态编码定义

| 状态码 | 中文描述 | 说明 |
|--------|----------|------|
| 0 | 待开赛 | 比赛尚未开始 |
| 1 | 进行中 | 比赛正在进行中 |
| 2 | 已结束 | 比赛已结束（从API获知），但还未获取详细赛果 |
| 3 | 延期/取消 | 比赛延期或取消 |
| 4 | 腰斩 | 比赛中途腰斩 |
| 5 | 中断 | 比赛中断 |
| 8 | 已获取赛果 | 比赛结束 + 详细赛果数据已成功保存（终态） |
| 9 | 异常 | 超过4天无结果且无延期标识 |

## 状态流转图

```
0 (待开赛)
    ↓
1 (进行中)
    ↓
2 (已结束) ← API返回比赛结束
    ↓
8 (已获取赛果) ← 成功获取并保存详细赛果数据（终态）

特殊状态：
- 3 (延期/取消): 任何时候都可能转入此状态
- 4 (腰斩): 从状态1转入
- 5 (中断): 从状态1转入
- 9 (异常): 状态2超过4天未获取到赛果时转入
```

## 关键设计原则

### 1. 状态2和状态8的区别

**状态2（已结束）**：
- 仅表示从API得知比赛已经结束
- 此时可能还没有详细的比分、赔率等赛果数据
- 是一个中间状态，需要继续尝试获取赛果

**状态8（已获取赛果）**：
- 表示不仅比赛结束，而且详细的赛果数据已经成功保存到数据库
- 包括比分、半场比分、角球数、红黄牌等完整信息
- 是终态，不再进行更新

### 2. 为什么要区分状态2和状态8？

**原因**：
1. **数据完整性保证**：确保只有在成功保存所有赛果数据后才标记为完成
2. **避免重复处理**：状态8的比赛会被跳过，不会重复获取赛果
3. **异常检测**：长期处于状态2的比赛可以被识别为异常（状态9）
4. **时序控制**：先确认比赛结束（状态2），再获取赛果（状态8），逻辑清晰

### 3. 状态更新时序

正确的状态更新流程：

```python
# 第一步：检测到比赛结束
match.status = 2  # 已结束
save_to_database(match)

# 第二步：获取详细赛果数据
result_data = fetch_match_result(match_id)

# 第三步：保存赛果数据
save_match_result(result_data)

# 第四步：更新状态为终态
match.status = 8  # 已获取赛果
save_to_database(match)
```

**错误做法**：
```python
# ❌ 错误：直接将比赛结束映射为状态8
match.status = 8  # 这样会导致在获取赛果前就标记为完成
```

## 辅助函数

### get_status_desc(status_code)

根据状态编码获取中文描述。

```python
>>> get_status_desc(2)
'已结束'
>>> get_status_desc(8)
'已获取赛果'
>>> get_status_desc(99)
'未知(99)'
```

### map_to_internal_status(source_type, source_status)

将不同数据源的状态值映射为内部统一的状态编码。

```python
>>> map_to_internal_status('bjdc', '完')
2
>>> map_to_internal_status('tczq', '2')
2
>>> map_to_internal_status('jcbk', 1)
1
```

### is_completed(status_code)

判断是否已完成（已获取赛果）。

```python
>>> is_completed(8)
True
>>> is_completed(2)
False  # 只是结束，还未获取赛果
```

### should_skip_update(status_code)

判断是否应该跳过更新（已完成或异常的比赛）。

```python
>>> should_skip_update(8)
True
>>> should_skip_update(9)
True
>>> should_skip_update(2)
False  # 需要继续尝试获取赛果
```

### should_skip_result_fetch(status_code)

判断是否应该跳过赛果获取（已获取赛果的比赛）。

```python
>>> should_skip_result_fetch(8)
True
>>> should_skip_result_fetch(2)
False  # 需要获取赛果
```

## 常见问题

### Q1: 为什么有些比赛长期处于状态2？

**A**: 可能的原因：
1. API暂时无法获取到详细赛果数据
2. 比赛数据异常，需要人工检查
3. 如果超过4天，会自动转为状态9（异常）

### Q2: 状态8的比赛还会更新吗？

**A**: 不会。状态8是终态，系统会跳过这些比赛的更新和赛果获取。

### Q3: 如何修复卡在状态2的比赛？

**A**: 
1. 手动触发赛果获取任务
2. 检查API是否正常返回数据
3. 如果确实无法获取，可以手动设置为状态9（异常）

### Q4: 状态9的比赛如何处理？

**A**: 
1. 人工检查比赛实际情况
2. 如果是数据问题，修复后重新设置为状态2
3. 如果确实无法获取，保持状态9
